# 사용자 흐름

> MVP 시점 문서를 2026-10 현재 코드 기준으로 고쳤다.

## 학부모 흐름
1. 프로그램 리스트 진입
2. 과목/지역/연령 기준으로 탐색
3. 프로그램 상세 확인
4. 체험수업 또는 레벨테스트 신청 버튼 클릭
5. 로그인 또는 회원가입
6. 신청서 작성
7. 신청 완료 → 내 신청내역(`/my/applications`)으로 이동(별도 완료 화면 없음)
8. 마이페이지(`/my`)에서 신청 현황 요약 확인
9. 자녀 관리(`/my/children`)에서 자녀 프로필 등록/수정
10. 내 신청내역(`/my/applications`)에서 상태 확인

## 학원(studio 운영) 흐름
1. 학원 가입 신청(`/studio/sign-up`) → 승인 대기(`/studio/pending`) → 운영자 승인 후 academy 계정으로 로그인
2. 선생님 명부 등록(선택, 선생님은 로그인하지 않음)
3. 수업 관리에서 `trial_class` 또는 `level_test` 수업 등록 — 운영 방식(상시 90일 롤링 / 기간 지정)과 요일별 시간을 정하면 회차가 자동 생성된다
4. 신청 관리(`/studio/cases`)에서 신규 신청 확인
5. 신청 상세에서 일정 확정 → 체험 완료(또는 취소/노쇼)
6. 체험 기록 작성 → [스탠다드] 학부모 리포트 발행(신청당 1회)
7. 등록 결과 기록(결정 전 · 고민 중 · 등록 완료 · 미등록 + 사유) → [스탠다드] 전환 분석

## 인증 정책 메모
- 학부모 공개 회원가입(`/auth/sign-up`)은 parent 계정만 만든다
- 학원 계정은 공개 가입 신청 + 운영자 승인으로만 만든다(초대 기능 없음)
- `/studio/*` 접근 주체는 academy 계정(그리고 organization이 있는 admin)으로 제한

## 상태 설계 메모
- 신청 상태 값은 `new | reviewing | confirmed | completed | canceled` 다섯 개를 유지
- 현재 흐름은 `new -> confirmed -> completed` 와 `-> canceled`다. `reviewing`으로 가는 액션은 없다(기존 데이터 호환용, 화면에서는 new와 같은 "신규 신청")
- 노쇼는 canceled + `no_show_at`. 체험 기록·리포트·등록 결과는 별도 테이블 축으로 분리됐다
