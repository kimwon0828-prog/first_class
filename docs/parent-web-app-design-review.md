# 학부모 웹 앱 디자인 이관 — 1차 로컬 검토

기준: origin/main `278580b`, iPhone 1.0.0(13)의 앱 홈·디자인 토큰·탭 캡슐.

## 적용 범위

- 홈: 큰 소개 문구 대신 지역/자녀 → 검색 → 과목 → 다음 행동 → 수업 → 학원 순서.
- 앱의 과목 이미지 12개를 2배 해상도로 재사용. 홈/수업찾기에서 동일 이미지 사용.
- 240×144 수업 이미지, 카드 테두리 제거, 실제 가격과 이번 주 예약 가능 일정 칩.
- 앱과 같은 `homeSection` / `loadCardSlots`를 재사용. 학년 조건 및 이번 주 일정 선별 후 최대 6개. 일정은 수업별 별도 요청 대신 일괄 조회.
- 다음 행동은 확정 일정 → 기존 리포트/후속 응답 → 자녀 등록 순서로 한 영역을 사용. 자녀 조회 오류를 자녀 없음으로 표시하지 않음.
- 공통 헤더 및 하단 324×66 캡슐, 4개 탭(홈/일정/기록/마이), 선택 배경. 키보드/상세 스크롤 숨김과 기존 URL·로그인 복귀·자녀 선택 유지.
- 화면 폭에 맞춰 최대 480px 중앙 열. 공개 범위는 기존 노원구 정책 유지.

## 검증

- typecheck, lint(경고·오류 0), 운영 빌드 통과.
- 기존 16-route shell, child 전달, 안전한 returnTo 검증 통과.
- 기존 native catalog slots / grouped fixtures 검증 통과.
- 실제 DB 읽기 비교: 공개 활성 수업 2개, 일정 317개, 일괄/개별 조회 불일치 0.
- 브라우저: 320/390/1280px 가로 넘침 없음, 하단 8px 여백 확인, 브라우저 오류 로그 0건. 모바일 홈 → 검색 → 검색 결과 → 수업 상세 연결 확인. 검색 조건 returnTo 유지 확인.
- 실제 학부모 로그인 후의 개인화 홈, 신청 저장·취소·리포트 쓰기는 이번에 검증하지 않음.

## 다음 이관 범위

1. 수업/학원 상세 본문, 날짜·시간 선택과 신청 화면을 앱 배치에 맞춤.
2. 일정·기록·리포트·마이 본문과 로그인 화면 비교 이관.
3. 로그인한 브라우저에서 전체 흐름 검수 후 배포.

이번 작업은 전체 페이지 이관 완료를 뜻하지 않는다. 상세/일정/기록/마이에는 공통 헤더·토큰·내비게이션만 적용된 상태다.
DB/migration/Studio/네이티브 앱 파일 변경 없음. 고객 데이터 쓰기·알림 발송·commit/push/배포 없음.

# 2차 — 학부모 웹 전체 앱 디자인 이관 (2026-10-25)

대표 결정(10-25): 학부모 웹은 랜딩으로 바꾸지 않고 앱처럼 운영한다. Next.js 웹 코드에 앱 디자인을 다시 입힌다(Expo 웹 빌드 아님).
기준: 앱 `release/store-final-20261022`(e708047) `src/app/**`, `src/ui/**`, `src/ui/theme.ts`, `design-ref/*.png`. 신청 동의는 앱 PR #1 `feat/marketing-consent`(2b7854e).

## 공통 바탕

- 토큰: 1차 `ParentAppShell` 에 앱 `theme.ts` 의 나머지 값(ink700/300, lineSubtle, fillSoft, warn, alert, danger, scrim, 반경 6/10/12/16/20)과 `--gutter: 20px`(앱 본문 좌우 20)을 더했다. 화면별 토큰은 만들지 않았다.
- 부품: `features/classes/ui/parent-app-ui.(tsx|module.css)` 한 곳에 앱 `Button`·`StatusBadge`·`TimeChip`·`FilterChip`·`Band`·`Section`·정보 줄·접는 항목·원형 로고·대표 이미지·하단 고정 바·`Loading`·`Notice`를 두고 모든 화면이 이것만 쓴다. 상호작용 부품(`StickyHeader`, 공유, 학원 문의 시트, 학원 상세 탭 줄)은 `parent-app-ui-client.tsx`.
- 아이콘: 앱 Feather 모양을 인라인 SVG로(`app-icon.tsx`). 과목 선 아이콘은 앱 `assets/subjects/*.svg` 를 `public/images/subjects/` 로 복사.
- 문구 규칙: `features/classes/lib/app-presentation.ts` 가 앱 `trialPriceInfo`(“체험 10,000원”, “무료 체험”, “체험비는 학원에 문의”), 날짜(“10월 27일 (화)”), 시간(“오후 1:00”), 카드 시간 칩(“화 13:00”), 과목 이름→아이콘 코드를 그대로 따른다.
  - Node ICU 는 `ko-KR` 12시간 표기를 “PM 1:00” 으로 내 브라우저(“오후 1:00”)와 달라 hydration 오류가 났다. 시간은 24시 값으로 직접 만든다.
- 하단 탭: 앱 `ParentFrame` 처럼 뒤로가기가 있는 화면(수업 상세·학원 상세·학원 목록)은 하단 탭을 숨기고, 신청 바가 있는 화면은 그 자리에 흰 고정 바를 둔다.

- 수업 상세 위치: 웹에 있던 네이버 지도를 남겼다(앱 코드는 주소 + 버튼, Figma `design-ref/05` 는 지도 자리 있음).
- 학원 상세 시간 칩: 앱은 신청 시트를 바로 연다. 웹은 그 시간을 고른 수업 상세(`?slot=`)로 간다(신청 시트 자동 열기는 기존 웹 흐름에 없음).

| 웹 | 앱 | 결과 |

- 동의 영역(앱 PR #1 과 같은 문구·순서):
  - 맨 위 “전체 동의”. 선택 항목을 물을 때만 “(선택 항목 포함)”을 붙이고, 누르면 선택 항목까지 함께 켠다/끈다.

  - 시트를 열 때 `getMyAcademyNewsConsentAction` 으로 읽는다. 이미 동의했으면 선택 항목 대신 “학원 소식을 받고 있어요 · 마이 › 학원 소식에서 바꿀 수 있어요” 한 줄만. 읽기 실패·비학부모면 묻지 않는다(앱과 같음).

- 신청 로직·검증·`returnTo` 는 그대로다(`useTrialApplicationForm`, `createTrialApplicationAction`, 로그인 전 초안 보관 → 로그인 후 2단계부터 이어 감). 훅에는 “성공 뒤 이동 전에 한 번 부를 함수(최대 4초)”만 더했다. 기존에는 성공 즉시 `/my/applications` 로 이동해 동의 저장 요청이 이동에 묻힐 수 있었다.

- 확인: typecheck·lint 0. 비로그인 390/320/1280 에서 시트 1·2단계, 2단계 “로그인하기” → `/auth/sign-in?returnTo=/classes/:id`. `/apply` 비로그인 → 같은 `returnTo` 로 로그인 이동. 3단계 동의 두 상태(묻기 / 이미 동의)는 저장소에 남기지 않은 임시 미리보기로 화면만 확인했다(동의 저장·신청 제출은 누르지 않음).

### 앱과 다르게 한 곳

- 신청 완료: 앱은 시트 안에 “체험 신청이 접수됐어요” 타임라인을 보인다. 웹은 기존대로 `/my/applications` 로 이동한다(신청 흐름 유지).
